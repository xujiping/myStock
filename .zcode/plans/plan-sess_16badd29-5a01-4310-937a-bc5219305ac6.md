# 航天图谱动态数据化：表结构 + 全链路开发计划

## 设计原则
- **独立一套表**，不复用现有 `ms_entries` 体系（语义不同：观点复盘 vs 产业链信息抽取，复用会污染 dashboard 逻辑）
- **复用现有基础设施**：ffmpeg/whisper 转写链路、multer 上传、OpenAI 兼容 LLM 调用模式
- **预留 category 维度**，当前只填 `rocket`，表结构未来直接支持卫星/通信/光伏
- **累加合并 + 来源可追溯**：每份资料抽取后 upsert 实体表，`source_ids` JSON 追踪来源
- **手动修正不被覆盖**：`manual_override` 标记保护人工修改

---

## 阶段 1：数据库表结构（server/db.js）

新增 6 张表，全部带 `category` 字段：

### 1.1 资料源 `ms_aerospace_sources`
上传的视频或文字资料，是抽取的输入。视频资料复用 ffmpeg→whisper 链路。
```
id, category(默认rocket), title, source_type(video|text),
video_path, audio_path, transcript(视频转写/文字直接内容),
extraction(AI抽取的原始JSON), status(uploaded|extracting_audio|transcribing|extracting|extracted|failed),
error, created_at, updated_at
INDEX(category, created_at)
```

### 1.2 公司档案 `ms_aerospace_companies`（规范化 + 可手动修正）
```
id, category, name(唯一per category), ticker, role(业务定位),
business_mix(JSON: [[名称,占比],...]), source_ids(JSON),
manual_override(默认0), created_at, updated_at
UNIQUE(category, name)
```

### 1.3 零部件 `ms_aerospace_components`
```
id, category, code(如"06"), name(唯一per category), description,
cost_share(如"30-35%"), art(视觉类型), source_ids(JSON),
manual_override, created_at, updated_at
UNIQUE(category, name)
```

### 1.4 公司-零部件关联 `ms_aerospace_company_links`（多对多）
```
id, category, component_id, company_id, source_ids(JSON), created_at
UNIQUE(component_id, company_id)
外键级联删除
```

### 1.5 整体成本结构 `ms_aerospace_cost_breakdown`
```
id, category, name(如"推进系统"), share(如60), color, sort_order,
source_ids(JSON), manual_override, created_at
UNIQUE(category, name)
```

### 1.6 分段 `ms_aerospace_stages`
```
id, category, code, name, description, sort_order,
source_ids(JSON), manual_override, created_at
UNIQUE(category, code)
```

## 阶段 2：AI 抽取链路（server/jobs.js）

### 2.1 `extractAerospace(sourceId)` 函数
- 读取 source 的 transcript/content
- 调用 OpenAI 兼容接口，prompt 要求输出结构化 JSON：
  ```json
  {
    "components": [{"code":"","name":"","description":"","cost_share":"","companies":["公司名"]}],
    "companies": [{"name":"","ticker":"","role":"","business_mix":[["业务",占比]}],
    "cost_breakdown": [{"name":"","share":60}],
    "stages": [{"code":"","name":"","description":""}]
  }
  ```
- prompt 强调：资料里有什么抽什么，没有的字段输出空数组；不要编造；公司名用资料中出现的名称
- 抽取结果写回 `ms_aerospace_sources.extraction`，然后调用 `mergeExtraction` 入实体表

### 2.2 `mergeExtraction(sourceId, extraction, category)` 函数（累加合并核心）
- 遍历 extraction.components：按 (category,name) upsert 零部件，append source_id；公司名先 upsert 公司再建 link
- 遍历 extraction.companies：按 (category,name) upsert，manual_override=1 的字段跳过
- 遍历 cost_breakdown / stages：同样 upsert
- 关键：`manual_override=1` 的记录，AI 不覆盖其已有字段值，只追加 source_id

### 2.3 复用 `processVideo` 模式
为 aerospace source 写一个轻量的 `processAerospaceVideo`，转写完成后自动触发 `extractAerospace`（或等手动触发，提供配置）。

## 阶段 3：后端 API（server/index.js）

新增路由（前缀 `/api/aerospace`）：
- `GET /api/aerospace/:category` — 返回合并后的完整图谱数据（companies+components+links+costs+stages），前端展示用
- `POST /api/aerospace/upload` — multipart 上传视频（字段 category, title, videos[]）
- `POST /api/aerospace/texts` — JSON 上传文字（字段 category, title, content）
- `GET /api/aerospace/:category/sources` — 资料列表（管理用）
- `POST /api/aerospace/sources/:id/extract` — 手动触发/重跑抽取
- `PATCH /api/aerospace/companies/:id` — 手动修正公司档案（设 manual_override=1）
- `PATCH /api/aerospace/components/:id` — 手动修正零部件（设 manual_override=1）
- `DELETE /api/aerospace/sources/:id` — 删除资料（同时清理无关联的实体？或保留实体，仅移除 source_id）

启动时调用 `enqueuePendingAerospaceProcessing()` 恢复中断任务，与现有逻辑一致。

- 复用 `UploadModal` 模式，新增"航天资料上传"入口（在 aerospace 视图内，非全局 modal）

### 4.3 分类 tab 激活
- `aerospace-tabs` 四个按钮接入状态，切换 category 重新 fetch（当前只有 rocket 有数据，其余提示"暂无资料"）

## 验证方式
- `npm run build` 通过
- `curl http://localhost:5174/api/health` 正常
- 上传一段航天产业链视频/文字 → 自动转写 → AI 抽取 → 图谱页展示抽取的公司和零部件
- 手动修正公司代码 → 再次上传新资料 → 修正值不被覆盖
- 移动端无横向滚动（rocket-infographic 已有响应式）

## 不做的事
- 不复用/改动现有 `ms_entries`/dashboard 逻辑
- 不引入新依赖（沿用 multer/mysql2/fetch）
- 不改现有观点归档页面
